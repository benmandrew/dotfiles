# Install Scripts

`install.sh` is the *bootstrap*: it checks the platform, installs the Xcode Command Line Tools (CLT) on macOS or `python3` through apt on Linux, and runs `install.py` on `/usr/bin/python3`. `installer/` is the runner, in Python, and every install step is a Python function in `installer/steps/`. `verify-install.sh` checks the result. `lint-templates.sh` backs `make lint-templates` and sits here so the `scripts/*.sh` lint glob covers it.

## Python

The installer supports Python 3.9 and newer, since the CLT ship 3.9.6, and uses the standard library alone, so a fresh machine needs nothing installed first. `install.py` puts `scripts/` on `sys.path` itself; an exported `PYTHONPATH` would reach every tool a step runs. `make lint-py` runs ruff and mypy, and `make test-py` runs `scripts/tests` on the interpreter `install.sh` would pick. mypy checks against 3.10, the oldest target it accepts, so run `make test-py PYTHON=/Library/Developer/CommandLineTools/usr/bin/python3` for the floor. CI's `python` job runs `make test-py` on that interpreter on macOS and on the newest release through `actions/setup-python`. The linters write no cache and python runs with `-B`, so nothing they leave can reach a commit. `make test-container` runs a whole install in a fresh Ubuntu 22.04 container.

## Running steps

Steps are *idempotent*, skipping a tool already present; `--upgrade` upgrades it instead, and `--verbose` streams output live.

`installer/plan.py` lists the steps for each platform by name, and `_step` looks each one up in `STEPS`, the dict in `installer/steps/__init__.py`. `Runner.run` holds a step's stdout and stderr in a log and prints its tail and path on failure; `Runner.finish` lists every failed step at the end, and the run exits 1. Both streams are held because installers draw progress on stderr. After a step of `SLOW_SECONDS` or more, two at present, the runner logs `<step> took <n>s`; tests give it a stopped clock, so the line never reaches the output they assert. `Console` writes to a copy of stderr taken before any step runs. The runner also closes a step's stdin and restores the terminal's line settings, since a step that dies in raw mode breaks the shell.

A step is a Python function run in the runner's process. Every command it runs gets the step's environment, `context.env`, which all steps share, so what one step puts there reaches the steps after it: the `PATH` from `brew shellenv` or the nix profile through `shell.source`, `~/.local/bin` after `install_uv` installs uv, and `~/.cargo/bin` through `tools.load_cargo_env`. A step that raises `StepFailed`, or any other exception, fails alone, and the run carries on.

A step with `fatal=True` ends the run when it fails, as `install_apt_packages_if_missing` and `install_perf` do on Linux. A prompting step takes `interactive=True`, which leaves its output live and its stdin open; `install_homebrew` is the only one, the CLT install sitting in `install.sh` because `/usr/bin/python3` is a stub without the tools. `install_zsh_completions` runs last, since it invokes each installed binary.

## Writing a step

**Register a function.** A step is a function of a `StepContext`, wrapped in a `Step` under its name in its module's `STEPS` tuple, and `installer/steps/__init__.py` lists the modules; `test_plan.py` fails a registered step that no plan runs. `context.run` raises `StepFailed` on a non-zero exit; where a command's failure must not fail the step, the step uses `context.call`, `context.capture` or `context.succeeds`, and `context.note` adds a line to the step's held output. `context.args` holds the arguments the plan gave the step, as the package list of `install_apt_packages_if_missing`. A step logs through `context.log`, and its `[install]` lines stay stable, since tests assert them. It reads the platform from `context.host`, which a test sets to run the other platform's branch, and `StepCase` in `tests/support.py` puts a fake `curl`, `gh` and `sudo` on `PATH`. `/usr/bin` stays off that `PATH`, since a CI runner has a `go` there and macOS a `jq`; `_SYSTEM_TOOLS` links in the basic tools a step may call. `context.tmpdir()` is removed when the step ends. `shell.source` sources a script in a bash of its own and adopts the environment it leaves, which is how the nix profile reaches the steps after `install_nix`. The shared helpers are `fetch.py`, `github.py`, `release.py`, `tools.py`, `brew.py`, `apt.py` and `shell.py`. A comment that gives a fix its reason moves with the code.

**Prove the binary runs.** An installer's exit status says nothing about what it left behind: `claude update` once exited 0 over an npm install, leaving the package's stub in place of the native binary. So every path that installs or upgrades an executable ends with `tools.require_runs(context, command, *probe)`, by absolute path where the step knows it, and the probe prints and exits with no network, GUI or writes. Vendor self-updaters, which fetch outside `fetch.download`, run under `tools.retry_once`. A fixed-path install calls `tools.note_shadowed`, which names a copy earlier on `PATH` without deleting it.

**Download through the helper.** Every fetch uses `fetch.download(context, url, dest)`, or `fetch.download_verified(context, url, dest, manifest_url)` where upstream publishes a SHA-256 manifest (a comment notes where none exists), and both raise `StepFailed` on failure. Where upstream publishes no manifest, as for Neovim, `github.download_verified` checks the asset against the digest GitHub records for it, and `release.download` builds the release URLs for the two `fetch` calls. `fetch.CURL` sets `-f --proto '=https' --tlsv1.2` and the retry options, and the API calls in `github.py` run it too; `--retry-all-errors` stays off, since it retries a 404 through the whole backoff. Vendor installers run from a downloaded file, never `curl | sh`; `tools.run_downloaded` does both halves. Extract with `release.unpack`, which runs `tar -xf`, never `-xzf`, so a `.tar.zst` needs no change.

**Pin versions.** Tags live in `pins.sh`, spelled exactly as upstream publishes them. `installer/pins.py` alone parses that file, and each pin stays one `NAME_VERSION="value"` line with no expansion and no trailing comment. A pin resolves through `pins.pinned_tag(context, name)`, which returns the newest tag under `--upgrade`. `UPSTREAM` in `pins.py` gives each pin its repository, and `test_pins.py` fails a pin without one. `make pins` shows which pins to bump by hand. `github.api_token` takes `GITHUB_TOKEN`, else `gh auth token`, since anonymous calls get 60 an hour; a failed call reports the rate-limit reset time from the response headers. `BTOP_VERSION` holds at 1.4.4, since later releases need GNU Compiler Collection (GCC) 14 and jammy ships GCC 11. WezTerm has no pin, upstream tagging no releases, and Obsidian on Linux uses `desktop_version` in `steps/obsidian.py`, since the newest release can be Android-only.

**Pin the system toolchain.** `install_btop` and `install_tmux_from_source` build with `SYSTEM_PATH` from `steps/builds.py` as their `PATH`, and with `CXX=/usr/bin/g++` and `CC=/usr/bin/gcc` respectively, because direnv's flake devShell puts a nix gcc wrapper first that cannot see `/usr/include`.

**Take cargo tools prebuilt.** `steps/cargo_tools.py` fetches release binaries into `~/.local/bin` using the asset names and *target triples* in its `TOOLS` table, falling back to `cargo install --locked` only where upstream publishes nothing; `--locked` stops eza's `palette` pin breaking. *musl* beats gnu wherever both exist, as in `install_atuin`, since gnu builds need a newer glibc than Ubuntu 22.04 ships. A copy in `~/.cargo/bin` counts as absent and is deleted, as `verify-install.sh` searches there first.

**Write exact guards.** Match the version number rather than a field, since `btop` and `atuin` pad theirs and tags carry a `v`; a mismatch reinstalls on every `--upgrade`, and a failing `--version` counts as absent. Guard every artefact, as `install_zstd` tests `apt.installed(context, "libzstd-dev")` beside `context.which("zstd")`.

**Keep apt non-interactive.** `LINUX.env` in `plan.py` sets `DEBIAN_FRONTEND=noninteractive` for every step, since a debconf dialog inside a held step is invisible. A step calls `apt-get`, never `apt`, which lacks a stable command-line interface (CLI), and a root-owned file is written with `tools.sudo_write`.

**Sudo.** `cli.run` calls `SudoSession.start_askpass` then `start_keepalive` before the first step; on macOS they must precede `install_homebrew`, whose installer runs `sudo -k` on exit unless sudo is already active. Homebrew resets the sudo timestamp on every invocation, so the *askpass helper* reads the password once and puts `SUDO_ASKPASS` in the steps' environment, which brew honours. A wrong password is asked for again, `PASSWORD_ATTEMPTS` times in all, and an empty one falls back to sudo's own prompts. A step runs a root command through `tools.sudo`, which adds `-A` through `sudo_command` when `SUDO_ASKPASS` is set; leave `-A` off a call that must never prompt. The keepalive runs `sudo -n true`, without `-A`, from a daemon thread and ignores its failures. `DOTFILES_NO_ASKPASS=1` disables the helper, and `HOMEBREW_NO_ASK=1`, set in `cli.run` alone, stops `brew upgrade` asking.

## Optional tools

Tools only useful on a machine someone sits at go into both plans as `OptionalStep(key, description, step)`. `OptionalTools.enabled` asks once, never infers, and records `name=yes|no` in `~/.config/dotfiles/optional-tools.conf` (respecting `XDG_CONFIG_HOME`). `--all-optional` and `--no-optional` decide without touching the file; `--reconfigure-optional` re-asks. The prompt reads `/dev/tty` and defaults to no; with no terminal the tool is skipped unrecorded. Test the terminal by opening `/dev/tty`, as `tty_available` does, since the device node is readable without one.

## Per-tool constraints

- `install_git` runs third on Linux, after the two fatal steps, fitting the git-core personal package archive (PPA) build on Ubuntu below `GIT_MIN_VERSION`, and fails if git is still below it afterwards; its key must match `GIT_CORE_PPA_FINGERPRINT`.
- `install_tmux_from_source` skips a tmux of 3.4 or newer, the first with the `hyperlinks` terminal feature; `install_neovim_if_missing` skips a Neovim of 0.12 or newer, for built-in completion.
- `install_login_shell` reads the shell from `getent passwd` or `dscl`, never `$SHELL`, which stays stale until the next login. It keeps any zsh already set and listed in `/etc/shells`, else sets `/usr/bin/zsh` or `/bin/zsh` with `sudo chsh`, and skips an account missing from `/etc/passwd`, which chsh cannot change.
- `install_perf` warns rather than fails without an exact-version kernel-tools package.
- `enable_nix_flakes` is only a fallback for a machine that has not run `chezmoi apply`; `home/dot_config/nix/nix.conf` is where nix settings belong.
- `configure_nix_trusted_user` adds the user to `trusted-users`, since the daemon silently ignores restricted settings from anyone else.
- `install_btop` purges packaged btop, which shadows `~/.local/bin`.
- `install_nix_direnv` downloads upstream's `direnvrc` at `NIX_DIRENV_VERSION` to `~/.local/share/nix-direnv/`, since `nix profile install nixpkgs#nix-direnv` took 18 seconds in CI to place that one file. Upstream attaches no file to a release, so `DIRENVRC_SHA256` in `steps/nix.py` holds the hash and moves with the pin; under `--upgrade` a newer tag is checked for its `NIX_DIRENV_VERSION` line alone. The step sets `NIX_DIRENV_FALLBACK_NIX` in `direnvrc`, which the nixpkgs build had patched in, and moves a machine off the profile entry: it rewrites the old `source` line first and runs `nix profile remove` last.
- `install_opam` is optional, since a machine with no OCaml compiles one for the default switch, 396 to 595 seconds on a CI runner. CI has no terminal, so it never runs the step and caches no opam root.
- `install_gh_stack` and `install_gh_stack_skill` need an authenticated gh, which nothing here provides; where `_authenticated` in `steps/gh.py` is false they log why and pass. The skill takes `--scope user`, since the default writes into the current repository. `gh skill` is a preview command and the likeliest to break.
- `install_obsidian`, the first half of the `install_obsidian_stack` step, installs the app, since the Obsidian CLI ships inside it and registers only by a settings toggle (`_cli_hint`). Linux ARM64 links the launcher as `~/.local/bin/obsidian-app`, leaving `obsidian` to the CLI, and makes `chrome-sandbox` setuid root, which Electron requires.
- Obsidian config lives in the vault's own `.obsidian/`; nothing there or in `~/.config/obsidian/` goes into chezmoi, since Obsidian and obsync rewrite it. The vault clone stays manual, its address exposing an otherwise proxied origin, so `_vault_is_ready` only checks for `~/projects/obsidian-vault` with the `personal` remote `obsync.sh` hardcodes. macOS schedules by LaunchAgent, its cron lacking Full Disk Access and Homebrew; `_schedule_launchd` calls `_remove_cron` only once the agent is loaded, and `_without_obsync` keeps a machine to one schedule.
- `install_site_fonts` is optional and installs the typefaces of benmandrew.com for Obsidian: Libertinus Serif and Iosevka Slab Extended, in regular, italic, bold and bold italic. macOS takes the `font-libertinus` and `font-iosevka-slab` casks. On Linux each family goes into its own directory under `~/.local/share/fonts`, unzipped with `-j` and only the faces it names. The Iosevka asset is the unhinted package, a 123 MB download against 179 MB hinted. Libertinus publishes no checksum and GitHub records no digest for it, so that download goes unverified. The fonts come from upstream, never from the site's woff2 files in another repository.
- `install_terminal_font` installs Iosevka Term Slab, WezTerm's text font, from the release zip on both platforms, since Homebrew has only its Nerd Font build, under another family name. It goes into `~/Library/Fonts/IosevkaTermSlab` or `~/.local/share/fonts/IosevkaTermSlab`, and takes only the six faces `wezterm.lua` resolves to: SemiBold, Heavy and Light, each with its italic. Change the weight there and `MEMBERS` in `steps/terminal_font.py` changes with it. The asset is the unhinted package, 117 MB against 170 MB hinted, and shares `IOSEVKA_VERSION` with the site fonts.
- zathura on macOS comes from the `homebrew-zathura/zathura` tap, which Homebrew 6 refuses per formula until trusted, so `install_zathura` checks `brew trust --json v1`; `Noah4ever/tap` in the `deps` Make target needs the same. `--with-synctex` goes on install and upgrade, since `zathurarc` relies on SyncTeX. `zathura-pdf-poppler` has its own guard, and `_link_pdf_plugin` runs every time, zathura scanning only `$(brew --prefix zathura)/lib/zathura`. Poppler is chosen over the recommended mupdf so both platforms share one renderer.
- `install_latex` on Linux installs upstream TeX Live per user into `~/.local/texlive/<year>`, its binaries linked into `~/.local/bin`, since apt holds TeX Live at the distro's year. It fetches `install-tl` and its SHA-512 from one mirror resolved from `mirror.ctan.org`, which otherwise serves the pair from different mirrors. `--upgrade` runs `tlmgr update` within a year and installs afresh only for a newer year, deleting the old year only after the new one runs; a year counts as installed only once `.dotfiles-complete` is written after install-tl, so an interrupted install is removed and redone; an installer older than the installed year, from a lagging mirror, is skipped. The apt TeX Live is left installed.
- No step registers Model Context Protocol (MCP) servers.

## `scripts/verify-install.sh`

`check_cmd`, `check_dir` and `check_file` fail the run. `check_cmd <name> [probe]` also runs the command from `/`, with `--version` by default, since a stub on `PATH` passes `command -v`; a new call needs a probe that exits 0 with no side effects, GUI or network, and `--no-probe` takes a comment saying why. `check_cmd_optional` warns, for `perf`, `obsidian`, `zathura`, `latexmk`, `biber`, `typst`, `docker`, `opam`, `ocamllsp` and `ocamlformat`, as does `check_optional`, a label plus command for the gh-stack extension and skill and the two site font families. `check_bash_version` requires bash 4.4 from a login shell via `env -i ... zsh -lc`, as direnv sees it. Plugins come from every `set -g @plugin` line in `~/.tmux.conf`, `wezterm`, the Nerd Font and Iosevka Term Slab are skipped on headless Linux, and an absent `wezterm` only warns on Linux ARM64, where `install_wezterm` has no build. `nvim` must be 0.12 or newer.

Anything the installer may legitimately skip needs a warning check here, or a correctly provisioned machine fails.
