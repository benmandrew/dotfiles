# Chezmoi Dotfiles

Personal dotfiles managed with [chezmoi](https://chezmoi.io) for cross-platform (macOS ARM64, Linux x86_64/ARM64) portability.

The chezmoi root is `home/` (see `.chezmoiroot`), so everything under it is relative to `~` on the target system.

## Templating

**Change detection (run_onchange scripts):**
```
# tmux-conf-hash: {{ include "dot_tmux.conf.tmpl" | sha256sum }}
```
Including a hash of a dependency in the script header causes chezmoi to re-run it when that file changes.

## Key Areas

- **Neovim config** — `home/dot_config/nvim/` — `home/dot_vimrc` is for real vim only; nvim never reads it.
- **Install scripts** — `scripts/` — see `scripts/CLAUDE.md` for the per-function breakdown
- **Tmux** — `home/dot_tmux.conf.tmpl` — Hacktober theme, kept in sync with WezTerm's. `status-left` shows the armed `C-a` prefix as a ` ⌃a ` chip mirroring WezTerm's, driven by `#{?client_prefix,…}` rather than by polling, since tmux repaints the status line as soon as the prefix state changes. The chip is constant-width and signals by colour alone, so arming the prefix does not shift the window list.
- **claude-aware panes** — `~/.claude/sessions/<pid>.json` records each live session's `cwd` and its agent identifier (`counter-fe`, the name `gwt` lists). Both terminals walk the pane's process subtree for a registered session and read the two off it, falling back to their old behaviour when there is none.
  - *cwd* — new tabs/panes open where claude is *actually* working, not where the shell is. The two diverge once claude chdir()s (entering a worktree, say) while the shell sits suspended and never re-emits OSC 7.
  - *name* — tabs and windows are titled by agent, since `#{pane_current_command}` is `claude` for all of them alike. `wezterm-notify.sh` names its OS notification with it too, matching by `sessionId`.
  - *task* — `home/dot_local/bin/executable_claude-tab-title <word>` overrides that identifier with what claude is working on, keeping the two-character suffix (`chezmoi-d8` with task `atuin` renders `atuin:d8`) so several agents in one project still read apart. It writes a separate file under `~/.claude/tab-titles/`, since Claude Code rewrites the session JSON on every status change; `--clear` removes it, and overrides whose session has exited are pruned on the next write.
  - *status* — WezTerm tabs render as ` <index> ▎<title> `, the `▎` (U+258E) coloured amber `#e0a33e` while the session is busy, bold blue `#6f9ede` when `~/.claude/tab-bells/<pid>` marks attention (written by `wezterm-notify.sh`, removed once the tab is focused), blue when idle past 60 seconds, dim otherwise. Unfocused tabs only, since the active tab's state is already on screen in the pane below it. tmux windows draw the same chip: `window-status-format` and `window-status-current-format` in `home/dot_tmux.conf.tmpl` render ` <index> <bar><name> `, with the name truncated to 24 characters by `#{=24:...}`, the width WezTerm truncates a tab title to (`TAB_TITLE_MAX_WIDTH`). Before that they were ` <index>  <name> `, two spaces, no bar and no truncation. The index is painted at low contrast on both, `#6d371b` on the current or active chip (the midpoint of that chip's orange and the bar's black) and `#464444`, the tab bar's hover grey, elsewhere, mirroring `TAB_INDEX_FG_ACTIVE` and `TAB_INDEX_FG_INACTIVE` in `wezterm.lua`.
  - WezTerm does this in-process (`claude_session` in `wezterm.lua`). tmux shells out to `home/dot_local/bin/executable_claude-pane-session`, which the status line polls per window every tick — so `status-left` rebuilds a shared cache once per tick and the per-window lookups only read it. The bar's colour comes back from that script already wrapped in its own `#[fg=…]`, which works because tmux expands a `#()` job's output as a format, applying a style sequence inside that output rather than printing it; confirmed by attaching a client over a pseudo-terminal and decoding the SGR codes off the rendered status line. The script gained two fields for this, `status` and `status-current`, rather than one field and a flag, because tmux picks the chip by choosing between the two format options and the script cannot see which window is current. `status-current` always answers with the dim colour. A window with no claude session in it gets no bar at all, matching the WezTerm tab, so the empty string is the answer rather than a lookup miss. The shared cache carries two record kinds to serve this. The `S` session line holds `status` and `statusUpdatedAt` beside the name and cwd, and a new `B <pid>` line records a bell, whose existence is its whole content, so there is no file to read. Both window styles restore the name's own foreground and weight after the index and bar, since setting `#[fg=]` at all is what overrode `window-status-style`. Only the `status` fields fork `date` for the current time; `name` is asked once per window per tick and would be paying for nothing.
- **Zsh completion** — `home/dot_zshrc.tmpl`. [fzf-tab](https://github.com/Aloxaf/fzf-tab) (cloned to `~/.local/share/fzf-tab` by `install_fzf_tab`) renders the completion menu as an fzf picker with per-context preview panes. Three things it depends on: `zstyle ':completion:*' menu no` (zsh's own menu would fire alongside it), `zstyle ':completion:*:descriptions' format` (its group headers come from that label), and being sourced after `~/.fzf.zsh` so it owns the `^I` binding. Make-target previews come from `_make_target_recipe`, which reads the recipe out of the makefile with awk — `make -n` would evaluate `$(shell ...)` on every keystroke. The picker is case-insensitive, which took an fzf flag rather than a completion setting. zsh's `matcher-list` already generated candidates case-insensitively: with it set, typing `Dow` produces `Downloads`, `dowager` and `downstream`, verified by driving an interactive zsh over a pseudo-terminal (pty) with fzf-tab disabled. fzf-tab then seeds fzf's query with the word already typed, and fzf is *smart-case*, so a query carrying an uppercase letter switches it to case-sensitive matching and the two lowercase candidates were filtered straight back out, leaving a picker that read as case-sensitive. `printf 'Downloads\ndowager\ndownstream\n' | fzf --filter=DOW` returns nothing; the same command with `-i` returns all three. So `-i` goes in the `zstyle ':fzf-tab:*' fzf-flags` line, at the cost of forcing a case-sensitive filter by typing a capital, which fzf has no per-keystroke toggle for. `${XDG_DATA_HOME:-$HOME/.local/share}/zsh/site-functions` is prepended to `fpath` before `compinit`, which reads `fpath` once. It holds the completion functions generated by `install_zsh_completions` in `scripts/install-common.sh`. Prepended rather than appended, so a generated function beats a system one claiming the same command name; before it there was no entry under `$HOME` on `fpath` at all, the five entries being system directories plus fzf-tab's lib. rustup ships `_cargo` and `_rustup` inside the toolchain, at `~/.rustup/toolchains/stable-<triple>/share/zsh/site-functions`, and puts them nowhere on `fpath`, so `cargo` and `rustup` completed nothing. That directory is added with a `stable-*` glob and the `(N)` qualifier, so a machine without rust does not hand compinit a path that does not exist. The glob matches more than one directory when a cross-compilation target is installed (this Mac has both `stable-aarch64-apple-darwin` and `stable-x86_64-unknown-linux-gnu`); the two carry the same functions, first match wins, and the extra costs compinit one directory scan a day. `delta --<TAB>` used to offer flags for Source Code Control System (SCCS). `_comps[delta]` read `_sccs`, because zsh's bundled `_sccs` registers the name `delta` for the SCCS subcommand of that name, and brew's `git-delta` ships no zsh function of its own. The fix is a real `_delta`, generated by `delta --generate-completion zsh` into the user directory; since that directory is first on `fpath`, compinit binds the name to it, and `delta --side<TAB>` now completes to `delta --side-by-side`. A guarded `compdef _delta delta` after compinit covers the case where the generated file is absent. Four further zstyles. `verbose yes` with `':completion:*:options' description 'yes'` puts each flag's description beside it, which the picker at 60% height has the width for. `special-dirs true` offers `.` and `..`, so `cd ..<TAB>` completes to `cd ../` where it previously completed nothing. `rehash true` makes completion notice a binary installed since the shell started, without a manual `rehash`. compinit's 24-hour freshness check no longer forks: it was `find "$ZDOTDIR/.zcompdump" -mmin -1440`, one fork on every shell startup, and is now zsh's own *glob qualifier*, `("${ZDOTDIR:-$HOME}"/.zcompdump(N.mh-24))` tested for emptiness. Measured in isolation the check went from 8.5 ms ± 0.8 to 6.1 ms ± 0.5, and whole-shell startup from 64.6 ms ± 2.1 to 58.0 ms ± 3.0. `install_zsh_completions` runs last in both platform scripts, since it invokes each binary to get its script. It covers `uv` (`generate-shell-completion zsh`), `uvx` (`--generate-shell-completion zsh`), `fd` (`--gen-completions zsh`), `delta` (`--generate-completion zsh`), `rustup` (`completions zsh`), `atuin` (`gen-completions --shell zsh`) and `chezmoi` (`completion zsh`). A tool whose completion is already installed system-wide is skipped rather than shadowed, so `brew upgrade` keeps ownership of it: on this Mac that skipped `atuin` and `chezmoi`, which brew links, and generated the other five. Homebrew links 38 completion functions on this Mac for comparison. On Linux none of the seven are skipped, which is the point, since `scripts/install-common.sh` drops those tools into `~/.local/bin` as bare binaries with no site-functions directory alongside, so Linux had completion for none of them. Output goes through a temporary file and is moved into place only when the generator exits clean and wrote something, so a generator that fails half way cannot leave a truncated function that breaks completion for that command until the next run. The step then deletes `.zcompdump` and `.zcompdump.zwc`, because compinit caches the command-to-function map in the dump and would otherwise wait out the 24-hour timer before seeing the new functions.
- **Shell autosuggestions** — [zsh-autosuggestions](https://github.com/zsh-users/zsh-autosuggestions), cloned to `~/.local/share/zsh-autosuggestions` by `install_zsh_autosuggestions`, greys in the rest of the most recent matching command after the cursor. It is sourced last of the line-editor plugins, because it wraps every zsh line editor (ZLE) widget that exists when it loads and has to see fzf-tab's and atuin's. Ordering matters for a second reason: `atuin init zsh` sets `ZSH_AUTOSUGGEST_STRATEGY` to atuin's own `atuin` strategy, which draws the suggestion from the synced database rather than this machine's `$HISTFILE`, and that only holds if atuin runs first (a live shell reports `strategy: atuin`). Nothing in the config sets the strategy, so atuin's assignment stands. `ZSH_AUTOSUGGEST_HIGHLIGHT_STYLE` is `fg=#6c6c6c`, since the default colour 8 is invisible on the Hacktober background, and `ZSH_AUTOSUGGEST_BUFFER_MAX_SIZE=80` stops the widget rescanning history on every keystroke of a pasted or very long line. Loading it costs nothing measurable at startup: two rc files differing only in this block benchmark at 62.1 ms ± 2.7 against 61.5 ms ± 3.2 over 80 runs each, a 0.6 ms gap against a 3 ms run-to-run spread.
- **Shell history** — [atuin](https://atuin.sh) replaces syncing a shared `~/.zsh_history` between machines, installed by `install_atuin` in `scripts/install-common.sh` (`brew install atuin` on macOS, the official GitHub release tarball into `~/.local/bin` on Linux x86_64 and ARM64) and sourced in `home/dot_zshrc.tmpl` after the fzf-tab block. The config is managed too, at `home/dot_config/atuin/private_config.toml`; chezmoi's `private_` prefix lands it at `~/.config/atuin/config.toml` with mode 0600, matching the permissions atuin itself writes and leaving room for the `extra_headers` key, which can carry proxy credentials. `sync_address` points at a Tailscale host, `enter_accept = false` puts the selected command on the prompt rather than executing it, `update_check = false` because the install scripts own the version, and `[ui] columns` includes `host`, which the default set omits, so a synced result shows which machine ran it. Carrying the history file itself in a git repo does not work: it only ever appends locally, so two machines that both ran commands produce divergent tails that git sees as an unresolvable conflict. Marking it `encrypted_` (age or gpg) makes that worse, since the blob changes completely on every command, every sync becomes a full-file rewrite and no conflict can be resolved by hand. atuin syncs individual command records into SQLite instead, so machines merge. Encryption still matters on a private server, because shell history routinely carries API keys passed as command arguments and internal hostnames; atuin's sync is end-to-end encrypted with a key that stays on the machine, so the server only ever holds ciphertext. That key lives at `~/.local/share/atuin/key` and is deliberately not managed by chezmoi; losing it loses the synced history, so it needs backing up out of band in a password manager. Three keybinding details. `atuin init zsh` has to come after the `[ -f ~/.fzf.zsh ]` line, because `~/.fzf.zsh` binds `^R` to `fzf-history-widget` and the later binding wins. It is passed `--disable-up-arrow`, which would otherwise bind `^[[A` and displace the existing `up-line-or-beginning-search` bindings. And `--disable-ai`, since 18.19 binds `?` at an empty prompt to a TUI that sends the typed question to a hosted service — which defeats the point of keeping the history on a private server. `HISTFILE`, `HISTSIZE` and `SHARE_HISTORY` stay in place and atuin keeps writing the history file, which remains the offline fallback. The sync address is a Tailscale MagicDNS name and sits in the public repo deliberately, since the https certificate puts it in the public certificate transparency logs regardless and access is gated by the tailnet access control list (ACL) rather than by the name being unknown. `atuin register` / `atuin login` and the seeding step `atuin import auto` stay manual, and deploying the server itself is out of scope for this repo. A first sync or a bulk `atuin import auto` can leave a write-ahead log that every later process has to map and replay — 1.97 GB of `history.db-wal` after seeding 29,988 commands on 17 August 2026, which cost 520 ms before the `^R` TUI painted against 8 ms once `sqlite3 ~/.local/share/atuin/history.db 'PRAGMA wal_checkpoint(TRUNCATE);'` had folded it back into the database. Each machine records its commands under a short name rather than its hostname, so the Mac records `mac` where it used to record `Ben-MacBook.local`. The mechanism is `ATUIN_HOST_NAME`, which atuin reads when recording a command. (`ATUIN_HOST_USER` overrides the user half of the same string and is deliberately left unset.) The map lives in `home/.chezmoidata.yaml` under `atuin.hostnames`, keyed on `.chezmoi.hostname`, the hostname with any domain stripped and the case as the machine reports it. Current entries are `Ben-MacBook: mac`, `ben: manc`, `emel: emel`, `fisk: fisk`, `windows: win`, `av2: av2` and `av3: av3`. The key is what the machine reports as its hostname, which is not necessarily the name it is known by elsewhere: the Manchester box answers `ben` while its tailnet name is `ben-manchester`, and an entry written against the tailnet name matched nothing, so that machine silently kept atuin's default until the key was corrected. `home/dot_zshrc.tmpl` looks the machine up at `chezmoi apply` time and emits `export ATUIN_HOST_NAME=<name>` inside the existing `command -v atuin` block; a machine absent from the map emits nothing and keeps atuin's default, so the map does not have to be exhaustive. The `host` column is narrow, and a full hostname is truncated or crowds the command out of the row, which defeats the reason `host` is in `columns` at all — telling at a glance which machine a synced result came from. So the column is written `{ type = "host", width = 5 }` rather than the bare `"host"`, which takes atuin's default width of 15; the field is fixed rather than sized to its contents, and a database holding only `mac`, `manc`, `emel`, `fisk` and `win` still rendered every host field padded to 15 cells in atuin's search view, so the default spent 15 columns on `mac` as readily as on a full hostname and the 10 saved go to the command column, the one with `expand = true`. Every name in `atuin.hostnames` is four characters or fewer and the width includes the gap before the command column, so 5 is the tight fit, four of name and one of separator; at width 4 a four-character name butts directly against the command with no gap. A name wider than the field is truncated with `…` rather than overflowing (a name like `ben-manchester` at width 5 renders `ben-…`), so an over-long name costs only legibility, and padding is by display width rather than character count, so an emoji name (2 cells) pads correctly. Resolving the name at apply time rather than with a runtime `case` on `$(hostname)` leaves each machine's rendered `~/.zshrc` carrying only its own name, and keeps the map in one file instead of spread through shell branches. The caveat is that it applies only to commands recorded from that point on. Records already written keep the hostname, and `--filter-mode host` reads the old and new strings as separate machines; atuin has no rename command, and synced records are encrypted per record on the server, so back-filling is not available.
- **Prose diffs** — `home/dot_local/bin/executable_git-prose-split` splits a paragraph into one sentence per line, wired in as the `diff=prose` textconv driver in `dot_gitconfig.tmpl` and applied to `*.md`/`*.tex`/`*.txt` and friends by `home/dot_config/git/attributes` (`core.attributesFile`). Prose written a paragraph to a line makes a one-word edit read as the whole paragraph replaced; splitting it drops the untouched sentences out of the hunk, and delta's within-line highlighting picks out the changed words in the ones that remain. Display only — git turns textconv off for `add -p`, `format-patch` and anything else whose output must stay applicable, so the split diff never round-trips. No `cachetextconv`: that cache is keyed on the blob rather than on the script, so it would serve stale splits after every edit to the splitter. The abbreviation list (`e.g`, `Fig`, `et al.`, initials) is what stops `Fig. 3` breaking mid-sentence.
- **VS Code** — `home/{Library/Application Support,dot_config}/Code/User/modify_settings.json.tmpl`, both one-liners including `.chezmoitemplates/vscode-settings-modify.sh.tmpl`; managed keys live in `.chezmoitemplates/vscode-settings.json.tmpl` (strict JSON, no trailing commas). It is a **`modify_` script, not a plain file**, because VS Code rewrites `settings.json` itself whenever a setting is toggled or a prompt is dismissed — managing it as a file made every such write trip chezmoi's "has changed since chezmoi last wrote it" prompt. The script receives the live file on stdin, strips JSONC comments/trailing commas, and `jq`-merges the managed keys over the top, so chezmoi owns a subset of keys and VS Code keeps the rest.
