# Chezmoi Dotfiles

Personal dotfiles managed with [chezmoi](https://chezmoi.io) for macOS ARM64 and Linux x86_64/ARM64. The chezmoi root is `home/` (see `.chezmoiroot`), so paths under it map to `~`.

## Templating

A `run_onchange` script re-runs when the hash of a dependency in its header changes:
```
# tmux-conf-hash: {{ include "dot_tmux.conf.tmpl" | sha256sum }}
```

## Key Areas

- **Neovim** — `home/dot_config/nvim/`; `home/dot_vimrc` is for vim only. Plugin setup lives in each lazy.nvim spec. `.config/nvim/after` stays in `home/.chezmoiremove`, since nvim sources any leftover file there. Language server protocol (LSP) completion items need the `o` flag in `'complete'`, and `autotrigger` stays off, since beside `'autocomplete'` it doubles requests. `lazy-lock.json` is managed, so a plugin update trips chezmoi's "has changed" prompt; the restore script saves the lock first, since lazy rewrites it as nvim starts.
- **Doom Emacs** — `home/dot_config/doom/` is Doom's private config; the clone in `~/.config/emacs` belongs to the optional `install_doom_emacs` step. `run_onchange_after_sync-doom-emacs.sh.tmpl` hashes only `init.el` and `packages.el`, the files that need `doom sync`. `doom install` takes `--no-config`, or Doom's template files trip chezmoi's "has changed" prompt. `init.el` is Doom's own template, excluded from `typos`. `themes/doom-hacktober-theme.el` copies the Hacktober colours Ghostty and tmux use; change them together.
- **Install scripts** — see `scripts/CLAUDE.md`. Every gitleaks call passes `--redact`. The history scan stays out of `make lint`, since a shallow clone passes it unscanned.
- **Nix and direnv** — `home/dot_zprofile.tmpl` sources the Nix profile ahead of Homebrew, since macOS updates strip the Nix block from `/etc/zshrc`. `source_nix_profile` unsets `__ETC_PROFILE_NIX_SOURCED` first and never sources `/etc/bashrc`, which kills the installer under `set -u`. `.zprofile` unsets it too, since a tmux server hands it to every pane. The login-shell bash probe in `scripts/verify-install.sh` is copied into `home/run_after_check-login-path.sh`, since a target has no source directory; change both together.
- **Template linting** — `scripts/lint-templates.sh` needs `--source .`, or `home/.chezmoidata.yaml` is skipped and renders silently lose blocks. The `make lint-zsh` strip pass stays, since a render covers only this machine's OS branch.
- **Terminal** — Ghostty is only a window around tmux, which owns tabs, splits and sessions. WezTerm is gone, and `.config/wezterm` stays in `home/.chezmoiremove`.
- **Tmux** — `home/dot_tmux.conf.tmpl` keeps its Hacktober theme in sync with `home/dot_config/ghostty/config.tmpl`. `status-right` forks once a tick at most. No continuum, whose save job cost 50 ms a tick. `terminal-features` is reset with `-su` before `-sa`, so a re-source adds no duplicate, and needs `hyperlinks`, or tmux strips OSC 8 links. `base-index` and `pane-base-index` are 1, matching the number key that reaches a window.
- **claude-aware panes** — every reader of `~/.claude*/sessions/<pid>.json` globs `~/.claude*` to cover the work profile: `home/dot_claude/executable_wezterm-notify.sh`, and `claude-pane-session` and `claude-tab-title` in `home/dot_local/bin/`. `~/.claude/tab-titles` and `~/.claude/tab-bells` stay single, a pid being machine-wide. tmux clears bells from its hooks; `wezterm-notify.sh` writes no flag for a window already on screen in a focused client, since no hook would fire to clear it. `claude-tab-title` writes its override to a file of its own, since Claude Code rewrites the session JSON constantly. Keep forks off tmux's per-window status path.
- **GNOME keybindings** — GNOME and Forge bindings live in `desktop_keys` in `home/.chezmoidata.yaml`, which feeds `run_once_configure-gnome-keybindings.sh.tmpl`; set them there, never in a script. Their 1–9 placeholder is a trailing `#`, since braces inside a template action break the `make lint-zsh` strip pass.
- **Zsh** — load order in `home/dot_zshrc.tmpl` matters: fzf-tab after `~/.fzf.zsh` so it owns `^I`, atuin after both so it wins `^R`, and zsh-autosuggestions last, so it wraps every zsh line editor (ZLE) widget and keeps atuin's `ZSH_AUTOSUGGEST_STRATEGY`.
  - fzf-tab needs `zstyle ':completion:*' menu no`. `make-target-recipe` reads recipes with awk, since `make -n` runs `$(shell ...)` per keystroke. Generated completions go first on `fpath`, before `compinit`, so `_delta` beats system functions like `_sccs`.
  - `~/.rvmrc` sets `rvm_ignore_dotfiles=yes` so `rvm get` adds no eager loads back. `LS_COLORS` is a literal, the block running before `PATH` is set. `GLOB_DOTS` stays unset, so `rm *` cannot take `.git`.
- **Shell history** — atuin. The public Tailscale `sync_address` is deliberate. `atuin.hostnames` in `home/.chezmoidata.yaml` keys on `.chezmoi.hostname` as the machine reports it, with names four characters or fewer. `HISTFILE` and `SHARE_HISTORY` stay set as the offline fallback. Manual steps: `atuin register`/`atuin login`, `atuin import auto`, and backing up the unmanaged `~/.local/share/atuin/key` in a password manager.
- **Git config** — in `dot_gitconfig.tmpl`, `core.pager` must sit under `[core]`; below `[diff "prose"]` git reads it as `diff.prose.pager`. `merge.conflictStyle` falls back to `diff3` below git 2.35, which treats `zdiff3` as fatal. The `seed-worktree` post-checkout hook is set in config, since `core.hooksPath` would replace every repository's own hooks. `git-seed-worktree` clones only copy-on-write, skips build directories that record absolute paths, and gives a file the main worktree's mtime only when the content matches, since commit times let a changed file look older than its object.
- **Prose diffs** — no `cachetextconv` for `executable_git-prose-split`, whose blob-keyed cache goes stale when the splitter changes. It passes files through `cat` under VS Code, whose gutter diff uses textconv, and without `GIT_PAGER_IN_USE`, so `git diff > x.patch` still applies.
- **Box tables** — `executable_unbox` matches box characters as alternations of literal strings, never bracket expressions, since one-true-awk is byte-oriented.
- **Claude Code settings** — `home/dot_claude/modify_private_settings.json.tmpl` is a `modify_` script because Claude Code rewrites and reorders the file; managed keys live in `.chezmoitemplates/claude-settings.json.tmpl`. The prefix is `modify_private_`; `private_modify_` silently leaves the file unmanaged. `PLUGINS` in `home/run_onchange_install-claude-plugins.sh` must list everything in `enabledPlugins`, which fetches nothing. `CLAUDE_CODE_SHELL` points the Bash tool at bash, since zsh does not word-split an unquoted `$var`; macOS's `/bin/bash` is 3.2.
- **Compaction** — `autoCompactWindow` is set as a setting, since `CLAUDE_CODE_AUTO_COMPACT_WINDOW` locks `/config` out. Compact summaries stay outside repos so gitleaks never scans them.
- **Two Claude accounts** — the `cc-work` alias is single-quoted so `$HOME` expands at run time. `home/dot_claude-work/` symlinks shared config to `../.claude/`. Credentials, `settings.json`, `projects/`, `history.jsonl` and `sessions/` stay per profile; `sessions/` is never linked, being mode 0700 with a `.key` per session. macOS keychain separation between profiles is untested.
- **Launcher icons** — `executable_recolour-icons` deletes only `.desktop` copies marked `X-Recolour-Icons=true`. It rewrites `%k` in `Exec=`, from which Zotero's launcher resolves its install directory. `Icon=` holds a theme name, never a path: GNOME Shell reads `.names` off the Settings icon, and a file icon has none, so the session fails to start. An `OnFailure=` drop-in on `org.gnome.Shell@.service` runs `recolour-icons --remove-all`, so the next login gets the system icons. On macOS, `AppleIconAppearanceTintColor` must name the swatch, since the default swatch follows the accent and writes no key.
- **VS Code** — `Code/User/modify_settings.json.tmpl` is a `modify_` script because VS Code rewrites `settings.json`; managed keys live in `.chezmoitemplates/vscode-settings.json.tmpl`.

Each rule above says what to preserve; the commit that introduced it records why.
